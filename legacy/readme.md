# Legacy Versions

## Overview

ACTA did not begin as the platform it is today.

Before becoming ACTA, the project went through multiple prototypes, rewrites, and major architectural changes. Each version explored different ideas, solved different problems, and contributed to the philosophy that now defines the project.

This directory preserves those historical versions.

They are not maintained, updated, or considered production releases. Instead, they serve as a record of how the project evolved over time.

Understanding these versions helps explain not only what ACTA is today, but also why it was built the way it was.

---

## Purpose of This Directory

The goal of the `legacy` directory is not to archive old code for nostalgia.

Its purpose is to document the evolution of the project.

Each version reflects:

- Different design decisions
- Different technical constraints
- Different user experiences
- Different architectural approaches
- Different stages of learning and experimentation

Together, they form the development history of ACTA.

---

## Evolution Timeline

### Cyber Terminal Era (Godot)

The earliest stage of the project.

Originally built in Godot, these versions explored a simple but unconventional idea:

> Productivity should be centered around completed actions rather than plans.

The terminal-inspired interface became one of the project's defining characteristics and laid the foundation for everything that followed.

**Versions**

- v0.2 — First public prototype
- v0.5 — Final Godot release

These versions focused on validating the core concept before any large-scale development began.

---

### Action Logger Era (Web)

The first transition from prototype to product.

Moving from Godot to the web dramatically improved accessibility, usability, and future scalability.

The project was now capable of serving as a practical productivity tool rather than an experimental prototype.

**Versions**

- v1.0 — Action Logger

This version established the first complete browser-based experience and proved that the action-first philosophy could work in everyday use.

---

### ACTA Era

Beginning with v2.0, the project adopted the name **ACTA**.

This was more than a rebranding.

It represented a shift from a simple action logger into a broader productivity platform built around a clear philosophy, modular architecture, and long-term vision.

**Versions**

- v2.0 — Foundation of modern ACTA
- v3.0 — Workflow and usability improvements
- v3.5 — Refinement and simplification
- v4.0 — Architectural maturity
- v4.5 — Identity, persistence, and sharing
- v5.0 — Ecosystem refinement and stability

Each release focused on removing limitations rather than simply adding features.

## Historical Context

ACTA was never developed from a fixed blueprint.

The project evolved through experimentation, iteration, redesign, and continuous refinement.

Many ideas were introduced, modified, simplified, or removed entirely as the product matured.

Each version represents a snapshot of that process.

The history preserved here is therefore more than technical documentation—it is a record of how the project's philosophy evolved over time.

---

## Legacy Philosophy

These versions are preserved exactly as they existed during development.

They do not necessarily represent current best practices, modern architecture, or the latest implementation standards.

Instead, they represent something equally valuable:

the experiments, decisions, mistakes, lessons, and discoveries that ultimately shaped ACTA.

Looking back at previous versions provides context for understanding why the project exists in its current form.

Progress is not only visible in the latest release.

Sometimes it is best understood by looking at where the journey began.

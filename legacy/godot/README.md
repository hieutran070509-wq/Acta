# Godot Prototype

## Overview

Before ACTA became a web application, it began as a small experimental project built with Godot.

At the time, the goal was not to create a complete productivity platform. Instead, Godot served as a rapid prototyping environment for exploring new ideas, testing interaction models, and validating the project's earliest philosophy.

Although development eventually moved away from Godot, many of ACTA's defining concepts were first explored during this stage.

The Godot prototype represents the earliest chapter of the project's history.

## Why Godot?

When development began, the objective was experimentation rather than long-term product development.

Godot provided a fast and accessible environment for testing ideas without requiring extensive knowledge of web technologies.

The focus was not game development itself, but rapid iteration.

The prototype explored several core concepts:

- Terminal-inspired interaction
- Keyboard-first workflows
- Command parsing
- Action logging
- Local data persistence
- Lightweight interfaces
- Productivity without schedules

This environment made it possible to validate the project's direction before committing to a larger implementation.

---

## Core Ideas Introduced

Many ideas that would later define ACTA first appeared during the Godot era.

### Action-First Productivity

Instead of focusing on future plans, the prototype emphasized recording completed actions.

This eventually became the foundation of ACTA's philosophy:

> Things done, not things planned.

### Terminal-Based Interaction

The earliest versions relied heavily on keyboard input and command-style interaction.

This approach reduced friction and allowed actions to be recorded quickly.

### Parser-Driven Workflow

User input passed through a parser capable of interpreting commands and actions.

Even in its earliest form, the parser became one of the most important systems in the project.

### History as a Permanent Record

Rather than treating completed actions as disposable data, the prototype began exploring the idea of preserving activity history as a long-term record of progress.

This concept would later become one of ACTA's core architectural principles.

---

## Lessons Learned

The Godot stage revealed several insights that shaped future development.

### Productivity Should Focus on Reality

Completed actions provide a more reliable reflection of progress than plans alone.

### Keyboard Interaction Reduces Friction

Fast input methods encourage consistent usage.

### Simplicity Improves Usability

Removing unnecessary complexity often creates a better experience than adding more features.

### The Parser Matters More Than the Interface

The way users communicate with the system became more important than visual presentation alone.

### History Is the Foundation

Statistics, progression systems, and long-term insights all depend on reliable historical data.

These lessons would later influence both the architecture and philosophy of ACTA.

---

## Why Move to the Web?

As the project evolved, the original prototype environment became increasingly restrictive.

The goal was no longer to validate an idea.

The goal was to build a real product.

Migrating to HTML, CSS, and JavaScript enabled capabilities that would have been significantly more difficult to achieve within the original prototype.

These included:

- Responsive layouts
- Browser accessibility
- Easier deployment
- Cross-platform compatibility
- Modern user interfaces
- Cloud synchronization
- Long-term maintainability

The migration was therefore primarily a product decision rather than a technical one.

## Technology Transition

| Godot Prototype | Web Platform |
|----------------|-------------|
| Terminal Layout | Responsive HTML Interface |
| Parser Logic | JavaScript Parser |
| ConfigFile Storage | Local Storage & Cloud Sync |
| Popup Windows | Modal Components |
| CLI Commands | Command Engine |
| Godot UI | Modern Web UI |

Although the technology changed, the underlying philosophy remained the same.

---

## Preservation

Development in Godot ended after v0.5.

No further updates were made once the web rewrite began.

The preserved files exist to document the project's earliest stage and provide historical context for later versions.

These prototypes should be viewed as experiments rather than production software.

---

## Historical Value

The Godot prototype represents the origin of ACTA.

Many of the ideas that define the project today—including action-first productivity, terminal interaction, parser-driven workflows, and history-based progression—were first explored here.

While the implementation itself was eventually replaced, its influence remains visible throughout the modern platform.
